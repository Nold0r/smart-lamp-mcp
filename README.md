# smart-lamp MCP

MCP-сервер для управления Wi-Fi лампами **Magic Home / Zengge (LEDENET)** из AI-агента
(Claude Code, Claude Desktop, Cursor и любых других MCP-клиентов). Цвета, белый свет с
температурой, яркость, готовые сцены и **светомузыка** по звуку, который играет компьютер.

Главная особенность: сервер **работает при включённом VPN**, даже если VPN забирает себе
весь трафик, включая домашнюю сеть.

```
ты:     сделай свет как на закате
агент:  set_scene("sunset") → verified: true, rgb=(255,90,25)
ты:     включи светомузыку в холодных тонах
агент:  start_light_music(palette="cool") → started, speaker="Наушники"
```

## Возможности

| Инструмент | Что делает |
|---|---|
| `get_state` | состояние лампы: питание, режим, RGB, белые каналы, яркость %, температура K |
| `power` | включить / выключить |
| `set_color`, `set_color_hex` | RGB-цвет (`255,90,25` или `#FF5A19`), с яркостью |
| `set_white` | белый свет из белых светодиодов: 2700 K (тёплый) … 6500 K (холодный), яркость |
| `set_brightness` | яркость с сохранением текущего цвета/температуры |
| `set_scene`, `list_scenes` | сцены: `rain`, `sunset`, `golden`, `night`, `daylight`, `morning`, `reading`, `cozy` |
| `start_light_music` | светомузыка; палитры `rainbow`, `warm`, `cool`, `rain`, `sunset` |
| `stop_light_music` | остановить шоу и вернуть свет, что был до него |
| `light_music_status` | удары, отправленные кадры, текущий цвет |
| `discover_lamps` | найти лампы в сети |
| `network_info` | диагностика: через какой интерфейс идёт связь в обход VPN |

Каждая команда изменения возвращает состояние, которое **лампа сама сообщила после команды**,
и флаг `verified` — совпало ли оно с заданным.

## Требования

- **Windows 10/11** (проверено). Управление лампой должно работать и на Linux/macOS; светомузыка
  использует захват системного звука (WASAPI loopback) и проверена только на Windows.
- **Python 3.10+** (проверено на 3.14).
- Лампа или LED-контроллер, который настраивается приложением **Magic Home Pro / Zengge** и
  отвечает в локальной сети на порт **5577** (протокол LEDENET). Проверено на `AK001-ZJ21413`.
- Компьютер и лампа в **одной локальной сети** (один роутер, не гостевая сеть).

## 1. Установка сервера

```powershell
git clone https://github.com/Nold0r/smart-lamp-mcp.git
cd smart-lamp-mcp
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Найдите лампу (VPN выключать не нужно):

```powershell
.venv\Scripts\python.exe magichome.py discover
# ip=192.168.0.154  mac=A1B2C3D4E5F6  model=AK001-ZJ21413  via Ethernet (192.168.0.103)

.venv\Scripts\python.exe magichome.py state        # прочитать состояние
.venv\Scripts\python.exe -m pytest -q              # тесты (нужен: pip install pytest)
```

Запомните **MAC** лампы — по нему сервер найдёт её, даже если роутер выдаст ей новый IP.
Если лампа одна, можно ничего не задавать: сервер найдёт её сам.

> Linux/macOS: вместо `.venv\Scripts\python.exe` используйте `.venv/bin/python`.

## 2. Подключение к агенту

Ниже `<ПУТЬ>` — полный путь к папке, куда вы клонировали репозиторий,
например `C:\Users\you\smart-lamp-mcp`. Указывайте **python из `.venv`**, а не системный.

### Claude Code

```powershell
claude mcp add smart-lamp --scope user -e LAMP_MAC=A1B2C3D4E5F6 -- "<ПУТЬ>\.venv\Scripts\python.exe" "<ПУТЬ>\server.py"
claude mcp get smart-lamp      # должно быть: Status: ✔ Connected
```

`--scope user` — сервер доступен во всех проектах. Перезапустите Claude Code, после чего просто
пишите в чате: «включи дождливый свет», «сделай теплее», «приглуши», «светомузыку!».
Удалить: `claude mcp remove smart-lamp -s user`.

### Claude Desktop

Откройте *Settings → Developer → Edit Config* (файл `%APPDATA%\Claude\claude_desktop_config.json`)
и добавьте:

```json
{
  "mcpServers": {
    "smart-lamp": {
      "command": "<ПУТЬ>\\.venv\\Scripts\\python.exe",
      "args": ["<ПУТЬ>\\server.py"],
      "env": { "LAMP_MAC": "A1B2C3D4E5F6" }
    }
  }
}
```

В JSON обратные слэши удваиваются. Полностью перезапустите Claude Desktop.

### Cursor, Windsurf, VS Code и другие MCP-клиенты

Это обычный **stdio** MCP-сервер, конфиг тот же, что для Claude Desktop:

- **Cursor**: `~/.cursor/mcp.json` (или `.cursor/mcp.json` в проекте) — блок `mcpServers` как выше.
- **VS Code (Copilot agent)**: `.vscode/mcp.json`, ключ `servers` вместо `mcpServers`,
  плюс `"type": "stdio"`.
- Любой другой клиент: команда `<ПУТЬ>\.venv\Scripts\python.exe`, аргумент `<ПУТЬ>\server.py`,
  транспорт stdio.

### Настройки (переменные окружения)

| Переменная | Зачем |
|---|---|
| `LAMP_MAC` | MAC лампы; нужен, если ламп несколько, и чтобы находить её после смены IP |
| `LAMP_HOST` | IP лампы — подсказка для первого подключения (иначе — поиск в сети) |
| `LAMP_SOURCE_IP` | принудительно задать локальный адрес компьютера для связи с лампой |

Последний найденный IP кешируется в `lamp_cache.json` рядом с сервером.

## Светомузыка без агента

```powershell
.venv\Scripts\python.exe lightshow.py                       # до Ctrl+C
.venv\Scripts\python.exe lightshow.py --palette rain --seconds 60
.venv\Scripts\python.exe lightshow.py --device "Динамики" --min-brightness 0.2
```

Звук берётся с **устройства вывода** (то, что вы слышите), а не с микрофона. Басы задают яркость,
удар баса — вспышка и смена цвета, высокие частоты ускоряют дрейф оттенка, громкость
подстраивается автоматически. После остановки лампа возвращается к прежнему свету.

## Как это работает с VPN

Многие VPN-клиенты (AmneziaVPN, WireGuard в режиме «весь трафик», некоторые OpenVPN-конфиги)
добавляют свой маршрут на домашнюю подсеть, например `192.168.0.0/24` с метрикой 0. Тогда
обычное соединение к лампе уходит в туннель, и лампа «пропадает».

Сервер **ничего не меняет в маршрутах и настройках VPN**. Он находит сетевой интерфейс
компьютера, который находится в той же подсети, что и лампа (туннельные интерфейсы
пропускаются), и привязывает к его адресу каждый сокет. Windows отправляет такие пакеты через
этот интерфейс, мимо туннеля. Поиск ламп (UDP broadcast на порт 48899) делается так же.

Проверить, через что идёт связь: `python magichome.py network` или инструмент `network_info`.

## Особенности ламп (замерено на реальном устройстве)

- **Частота команд.** Одно постоянное соединение выдерживает 10 команд/с; на 20 команд/с лампа
  зависает на несколько секунд. Новое TCP-соединение на каждую команду исчерпывает слоты лампы
  после ~5 подключений. Поэтому всё идёт через одно соединение с лимитом **5 команд/с**
  (жёсткий потолок 10).
- **Плавный переход.** Лампа сама переходит к новому цвету за ~0,3–0,6 с, поэтому светомузыка
  мягкая, а не стробоскоп; слать чаще 5 раз в секунду смысла нет.
- **Флеш-память.** Последний байт команды: `0x0F` — сохранить во флеш, `0xF0` — временно.
  Светомузыка шлёт временные команды, чтобы не изнашивать память лампы.
- **Белые каналы.** Сумма тёплого и холодного ограничена 255 (это 100 %); значения лампа
  округляет на ±1–4.
- **Формат команды.** Используется 9-байтовая команда цвета; 8-байтовая на этой модели гасит свет.
- После команды лампа может прислать push-пакет `b0 b1 b2 b3 …`, парсер его пропускает.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `discover` ничего не находит | компьютер и лампа в одной сети? не гостевая ли Wi-Fi (там изоляция клиентов)? `magichome.py network` показывает интерфейс в подсети лампы? |
| «No local (non-VPN) interface is in the same subnet» | лампа в другой подсети, чем компьютер; или VPN-интерфейс назван необычно — задайте `LAMP_SOURCE_IP` |
| таймауты, `unreachable` | лампа перегружена: подождите 5–10 с; закройте приложение Magic Home на телефоне — оно занимает слоты соединений |
| найдено несколько ламп | задайте `LAMP_MAC` |
| светомузыка не реагирует | звук играет через устройство по умолчанию? иначе `--device` / параметр `device`; проверьте `light_music_status` |
| агент не видит инструменты | путь к python из `.venv`? `claude mcp get smart-lamp`; перезапустите клиент |

## Структура

- `magichome.py` — протокол LEDENET, обход VPN, поиск ламп, постоянное соединение с лимитом, CLI.
- `server.py` — MCP-сервер (stdio).
- `lightshow.py` — светомузыка (класс `LightShow` + CLI).
- `test_magichome.py` — тесты протокола на реальных ответах лампы.
